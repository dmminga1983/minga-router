# minga-router

**Хватит платить по тарифу Opus за исправление опечаток.** Скилл для Claude Code, который смотрит на каждую задачу *до* того, как она уйдёт субагенту, и отдаёт её самой дешёвой модели, которая с ней справится: Haiku — для мелочей, Sonnet — для средних задач, Opus — только когда этого действительно требуют сложность или риск.

Без вызовов API, без файла настроек, без фоновых процессов. Это один `SKILL.md`: Claude читает его и сам, бесплатно, применяет таблицу маршрутизации перед каждой передачей работы через `Task`/`Agent`.

## Почему это экономит реальные деньги

Обычно работу субагентам отдают одним из двух способов, и оба переплачивают:

- **Максимальные настройки всегда, «на всякий случай».** Opus с высоким усилием на задачу, где нужен один поиск и правка одной строки. Вы платите как за премиальную модель за то, что дешёвая сделала бы с первого раза.
- **Экономия наугад.** Дешёвая модель выбирается вручную, а результат потом никто не проверяет. Каждый вызов дешевле, но часть ответов приходит с ошибками, и их никто не ловит. Узнаёте об этом, когда что-то дальше по цепочке уже сломалось.

minga-router не делает ни того, ни другого. Он оценивает задачу по двум осям — **сложность** (сколько реальных рассуждений нужно) и **риск** (во что обойдётся ошибка), — выбирает самый дешёвый подходящий уровень и **всегда проверяет результат**. Если дешёвая попытка не прошла проверку, задача поднимается на уровень выше и выполняется заново — вместо неверного ответа или дорогого вызова без подстраховки. Именно этот шаг делает экономию безопасной: вы не меняете надёжность на меньший счёт, а просто не переплачиваете за лёгкие 80% задач, сохраняя прежнюю тщательность на сложных 20%.

## Как это работает

| Сложность | Риск | Модель | Усилие | Проверка |
|---|---|---|---|---|
| низкая | низкий | Haiku | низкое / по умолчанию | не нужна — результат очевиден (опечатка, форматирование, простой поиск) |
| средняя | средний | Sonnet | среднее | беглая — соответствует запросу, ничего явно не сломано |
| высокая | высокий | Opus (или Sonnet с высоким усилием) | высокое | полная — построчно по каждому требованию |

Пограничные случаи округляются вверх: недооценка риска обычно обходится дороже, чем несколько лишних центов за более дорогую модель.

**Модель текущего разговора при этом не меняется.** Скилл управляет только работой, которую *этот* Claude передаёт дальше через `Agent`/`Task`. Если в сессии нет субагентов — маршрутизировать нечего.

## Установка

Скопируйте `SKILL.md` в папку скиллов:

```bash
mkdir -p ~/.claude/skills/minga-router
curl -fsSL https://raw.githubusercontent.com/dmminga1983/minga-router/main/SKILL.md -o ~/.claude/skills/minga-router/SKILL.md
```

(Или скачайте репозиторий и сами положите `SKILL.md` в `~/.claude/skills/minga-router/`.) Claude Code подхватит его в следующей сессии — без перезапуска, настроек и включения.

## Со временем становится точнее

Настоящего обучения здесь нет — весов, которые обновлялись бы, тоже, — но есть практичная замена: с вашего разрешения (скилл один раз спрашивает в каждом проекте, прежде чем что-то записать) каждая проверка (успех или подъём на уровень выше) записывается в `.minga-router-log.md` в вашем проекте. В журнале только тип задачи, какая модель пробовалась и прошла ли проверка. Откажетесь, и маршрутизация работает так же, просто без самообучения. Когда за ~15–20 записей проявляется устойчивая закономерность — тип задач, который всегда приходится поднимать, или такой, где дорогой уровень раз за разом справляется с запасом, — скилл предлагает обновлённую таблицу маршрутизации с учётом этой закономерности. Вы её просматриваете и утверждаете. Молча свои правила он не переписывает никогда.
